## 1. 环境事实

本机为 NVIDIA GeForce RTX 4090 D，显存 24GB（实测空闲 21.7GB），llama.cpp 使用 CUDA 13.4 版本，位于 `D:\software\llama-b11159-bin-win-cuda-13.4-x64`。显存充足，嵌入模型与聊天模型可同时驻留。

| 角色 | 模型 | 量化 | 大小 |
|---|---|---|---|
| 嵌入 8B（主力） | Qwen3-Embedding-8B | Q5_K_M | 5.2 GB |
| 嵌入 4B（候选） | Qwen3-Embedding-4B | Q5_K_M | 2.8 GB |
| 聊天 4B | Qwen3.5-4B | Q5_K_M | 3.0 GB |
| 嵌入 12B（横向对比） | KaLM-Embedding-Gemma3-12B | i1 Q5_K_M | 8.1 GB |

模型文件统一位于 `D:\llamacpp_models` 目录下，按厂商与系列分子目录存放。

## 2. 模型服务启动

### 2.1 两个服务

嵌入服务监听 8081 端口，聊天服务监听 8080 端口。二者是两条独立的 llama-server 进程，分别加载不同模型，互不干扰。

```powershell
llama-server.exe -m D:\llamacpp_models\qwen3-embed\Qwen3-Embedding-8B-Q5_K_M.gguf --embedding --pooling last -c 8192 -b 8192 -ub 8192 --host 127.0.0.1 --port 8081
```

```powershell
llama-server.exe -m D:\llamacpp_models\qwen3.5\Qwen3.5-4B-Q5_K_M.gguf -c 8192 -b 8192 -ub 8192 --host 127.0.0.1 --port 8080
```

### 2.2 参数含义

| 参数 | 含义 | 类比 |
|---|---|---|
| `-m` | 模型文件路径 | 烘焙的原料 |
| `--embedding` | 嵌入模式，只输出向量不做对话 | 文字变数字的编码器 |
| `--pooling last` | 取最后一层隐藏状态做句子向量 | 一串数字里挑最有用那个 |
| `-c 8192` | 上下文窗口（token 数） | 一次能记住多长输入 |
| `-b` / `-ub` | batch / ubatch 大小 | 一次处理多少块 |
| `--host 127.0.0.1` | 只监听本机 | 不上公网，防偷窥 |
| `--port` | 服务端口 | 门牌号 |

### 2.3 启动输出解读

出现 `model loaded` 与 `listening on http://127.0.0.1:8081` 即表示服务就绪。聊天服务启动时的 `unused tensor blk.32.*` 警告来自 MTP（Multi-Token Prediction）模型的多余预测层，chat 模式用不到这些层，llama.cpp 自动忽略，属于正常现象，不是错误。

## 3. 验证：向量维度

用一段三行脚本调用嵌入服务，确认模型输出维度。Qwen3-Embedding-8B 实测返回 **4096 维**向量（4B 版本为 2560 维，KaLM 12B 待实测）。维度是存储层建表的关键参数——chunks 表要按维度存向量，换模型必须重建知识库。

```
POST http://127.0.0.1:8081/v1/embeddings  {"model": "qwen3-embed", "input": "你好世界"}
→ dim: 4096   head: [0.0246, -0.0055, 0.0031, ...]
```

## 4. 向量化最佳输入格式

### 4.1 结论

**保留标题结构的轻量 Markdown 是最佳输入格式**。PDF、Word 等二进制格式对 embedding 模型不可见，模型只能看到解析后的文字流。

### 4.2 三层理由

1. **tokenizer 视角**：embedding 模型按 token 读取文本，格式问题的本质是"希望模型从哪些字符里提取语义"。
2. **标题是语义结构**：Markdown 的标题层级是语义边界，与手写 RAG 的标题切块策略（按【】分节）完美咬合。切块是检索质量的第一道闸门，标题把这道闸门留给了 Markdown。
3. **管线归一化**：任何文档经 anydoc 统一转为 Markdown 后，切块与向量化只需处理一种格式，加新格式只动转换层——这是把异构入参收敛到一个入口的重构思想。

### 4.3 管线形态

```
PDF / Word / PPT / 图片 ──▶ anydoc 归一化 ──▶ Markdown ──▶ 标题切块 ──▶ 向量化
```

实操细节：装饰性标记（超长链接、代码注释）会稀释向量但影响很小；真正要保留的是标题层级。500 字切块约 600 至 800 token，8B 的 8192 token 上下文绰绰有余。

## 5. 横向对比候选

KaLM-Embedding-Gemma3-12B 已就位（i1 量化，Q4_K_M 6.9GB / Q5_K_M 8.1GB），可作为与 Qwen3-Embedding-8B 的检索命中率对照实验。其输出维度待起服务后实测确认，横向对比的判据沿用余弦相似度 top-k 命中率，不凭感觉。

## 6. 踩坑与安全

1. **MTP 模型的 unused tensor 警告不是错误**，忽略即可。
2. **CORS 全开警告**：本机调试无碍，但上公网前必须加 `--api-key`，否则任何能访问端口的人都能调用模型。
3. **`--pooling last` 必须带**：Qwen3-Embedding 官方要求 last 池化，缺失会导致向量化出错；编码模型与聊天模型的启动方式不同，嵌入模式必须同时加 `--embedding` 与池化参数。
