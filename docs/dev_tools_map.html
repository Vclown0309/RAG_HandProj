开发工具融会贯通地图
一个工具 = 一个函数：弄清 输入→输出、坏了查哪、融会标志 三点，工具就长在身上

→

→

→

git 存档
uv · 环境快递
菜谱 pyproject.toml → 厨房 .venv
坏了查：装包失败看源（清华已默认），uv.lock 与 pyproject 对不上就 sync
融会：新机器 uv sync 一键跑起
ruff · 代码体检
代码 → 违规清单 / 自动排版
坏了查：报错首字母（E/F 等）是规则编号，搜它定位；豁免用 # noqa 或改配置
融会：看别人代码 3 秒指出风格问题
mypy · 类型体检
注解代码 → 类型错误清单
坏了查：报错带行号，追那个变量在哪分支可能变 None
融会：写完函数主动想“None 会进来吗”
pytest · 验收工程师
tests/ 测试 → PASS / FAIL 报告
坏了查：FAIL 里 assert 那行就是证据，红的就是坏的
融会：先写测试再写实现（TDD 习惯）
git · 时间机器
工作区改动 → 可回滚的 commit 历史
坏了查：git status 看当前在哪个区（工作区/暂存/HEAD）；删错用 reflog 捞回
融会：合并冲突敢自己解，坏了能自己救
练法 · 破坏-修复循环：每个工具花 10 分钟故意弄坏再修好 —— 删掉 name: str 注解让 mypy 报错再补回；写错断言让 pytest 红再改对；乱排缩进让 ruff 报错再 ruff format 救回；commit 后 git reset --soft 看历史变了再 reflog 捞回。每走一遍，工具就从“鸟名字”变成“你手上的零件”。
